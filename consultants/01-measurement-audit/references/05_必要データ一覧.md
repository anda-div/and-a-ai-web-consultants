## GA4 から自動で取れるもの（同梱GASを1回実行すれば全部揃う）

`gas/GA4_GroundTruth_監査データ取得.gs` の `runGroundTruth` を実行すると、GT01〜GT09 の9シートが作られる。
**GA4 Data API で取得できるものは、この1本ですべて取る方針**にしている。
監査の途中で「あのディメンションも要る」と分かって取り直すのが、いちばん時間を食うため。

| シート | 内容 | 何が検査・確定できるか |
|---|---|---|
| GT01_イベント別 | eventName × 件数・ユーザー数・**キーイベント数**（全イベント） | I-02, **I-03**, **I-04**, I-10 |
| GT02_ページ別 | pagePath × 表示回数・ユーザー・セッション・イベント数・キーイベント・直帰率・エンゲージ率・平均エンゲージ時間・収益 | **I-01**, I-07 |
| GT03_イベント×ページ | eventName × ページパス+クエリ × ページタイトル × 件数・ユーザー数（全イベント） | **I-05（最重要）**／scroll のページ別到達／click のページ別集中 |
| GT04_離脱クリック先 | **発生ページ × リンクドメイン × リンクURL** × クリック数 | **I-06 の確定**（どのページからどのドメインへ出たか） |
| GT05_ページタイトル一覧 | pageTitle × 表示回数・ユーザー数 | I-08 |
| GT06_KPI | セッション・ユーザー・新規・PV・エンゲージ率・直帰率・イベント総数・キーイベント合計・収益 | 突合、I-03 の分母 |
| GT07_ページ間遷移 | pageReferrer × ページパス+クエリ × 遷移PV | 内部導線の再現、遷移元の集計 |
| GT08_CTA到達と転換 | ページ別「閲覧者／縦90%到達／到達率」の組み立て済み表 | CTA到達率の定量根拠（CV定義が未確定でも試算できる） |
| GT09_取得メモ | 取得条件の記録 | 再現性の担保 |

これに加えて必要なのは、対象レポートのファイル（PPTX/PDF）だけ。

## GA4 の「設定」も自動で取れる（もう1本のGAS）

`gas/GA4_GroundTruth_設定監査取得.gs` の `runConfigAudit` を実行すると、CF01〜CF11 が作られる。
**数値を取るGASとは別物**で、こちらは Admin API から**設定そのもの**を読み出す。
複数プロパティを一度に監査できる。

| シート | 内容 | 何が確定できるか |
|---|---|---|
| CF01_プロパティ／CF02_データストリーム | 測定ID・ドメイン・所属アカウント | 対象範囲の確定 |
| CF03_拡張計測機能 | scroll / 離脱クリック / フォームの操作 等のON/OFF | I-05・I-06 のイベントの出どころ |
| **CF04_キーイベント** | **何がCVとして登録されているか**（発生0件でも出る） | **I-03** |
| **CF05_作成イベント** | **「イベントを作成」の条件** | **I-04（0件イベントの原因）** |
| CF06_イベント編集ルール | イベント名・パラメータの書き換え | 意図しない改変の検出 |
| **CF07_Google広告リンク** | リンク先CID・パーソナライズド広告 | **I-03 の実害範囲** |
| CF08_カスタム定義 | カスタムディメンション／指標 | 取得計画との突合 |
| **CF09_変更履歴** | いつ誰が設定を変えたか | 「設定したが動作確認されていない」の裏づけ |
| CF10_その他の設定 | データ保持・アトリビューション・BigQuery | 次回以降の検証精度 |

> 「イベントを作成」はGA4のUIでは**データストリーム単位**にあり、プロパティの
> 「イベント」画面からは一覧に辿り着けないことがある。APIで取るほうが確実。

## それでも取れないもの（人にお願いする）

| # | データ | 取得元 | なぜ必要か |
|---|---|---|---|
| 1 | **内部トラフィックの定義／除外する参照のリスト／クロスドメイン測定のドメイン設定／Googleタグの「接続済みのタグ」** | GA4「管理 → データストリーム → Googleタグ →『タグの設定を行う』→ 設定を編集」 | Admin APIに含まれない。I-06・I-07 と、二重発火の原因特定に必要 |
| 2 | **実サイト**（主要ページのCTAのリンク先） | ブラウザで実物を確認 | I-06。リンク先が外部ドメインかどうかは、GA4だけでは絶対に分からない |
| 3 | Search Console の検索パフォーマンス（クエリ別＋日別） | Search Console のエクスポート | I-09 クエリ被覆率、SC数値の突合。GA4とは別ツール |
| 4 | GTMコンテナのエクスポート（JSON） | GTM | I-01・I-04 の**原因**の特定。事象自体はGA4データで確定済みなので、原因特定のためだけに必要 |
| 5 | フォームのテスト送信の結果 | 実際に送信して確認 | 「本当に0件」なのか「計測できていないだけ」なのか。**5分で確定する** |
| 6 | ヒートマップツールのセッション数 | Clarity 等 | 定性データのサンプル数。これが無いと結論の信頼度を判定できない |

## 依頼の文面テンプレート

### GAS の実行を依頼する場合

> 検証のため、GA4から次のデータをご取得いただけますでしょうか。
>
> 1. 添付の `GA4_GroundTruth_監査データ取得.gs` を Apps Script に貼り付けてください。
> 2. 冒頭の設定を書き換えてください。
>    - `GT_PROPERTY_ID` … 対象のGA4プロパティID
>    - `GT_START` / `GT_END` … 対象期間（レポートの対象期間と同じにしてください）
>    - `GT_SPREADSHEET_ID` … **空 `""` のままで構いません**（実行アカウントのドライブに
>      新規作成され、URLが実行ログに出ます）。既存のシートに書きたい場合だけIDを入れてください
> 3. 「サービス（＋）」から **Google Analytics Data API**（識別子 `AnalyticsData`）を追加してください。
> 4. 関数 `runGroundTruth` を実行してください。初回は権限の承認が必要です。
> 5. できあがったスプレッドシートを Excel 形式でダウンロードしてお送りください。
>
> 所要時間は5分程度（実行そのものは1〜3分）です。GT01〜GT09 の9シートが作られます。
>
> GA4 Data API で取れるものはこの1本ですべて取る作りにしています。
> 追加でお願いする可能性があるのは、APIから読み取れないもの
> （キーイベントの登録一覧の画面キャプチャ／GTMコンテナ／Search Console／テスト送信の結果）だけです。

### エラーが出たときの切り分け

| エラー | 原因と対処 |
|---|---|
| `You do not have permission to access the requested document.` | `GT_SPREADSHEET_ID` のシートに、実行アカウントの編集権限が無い。シートを共有するか、`GT_SPREADSHEET_ID` を `""` にして実行し直す（新規作成される） |
| `AnalyticsData is not defined` | 「サービス（＋）」で Google Analytics Data API（識別子 `AnalyticsData`）が未追加 |
| `User does not have sufficient permissions for this property.` | 実行アカウントに、そのGA4プロパティの閲覧権限が無い |
| `Exceeded maximum execution time` | GT03 の行数が多い。`GT_EVENTS_TO_SPLIT` に必要なイベント名だけを列挙して絞る |

### キーイベント一覧の画面キャプチャを依頼する場合

> GA4の「管理 → キーイベント」の画面を、スクロールして全件が見える形で
> キャプチャいただけますでしょうか。
> 何がコンバージョンとして登録されているかは、この画面でしか確認できません。
> （レポートやAPIからは「登録されているか」が読み取れないためです）

### テスト送信を依頼する場合

> フォームの送信が「本当に0件だった」のか「計測できていないだけ」なのかで、
> 打ち手が正反対になります。5分で確定できますので、次をお試しください。
>
> 1. ＜フォームのURL＞ をテスト内容で実際に送信する
> 2. 送信直後のブラウザのURLを控える（変化があるか）
> 3. すぐにGA4「レポート → リアルタイム」の「イベント数（イベント名別）」を見る
>
> - `form_submit` が現れれば → 計測は生きており、対象月の送信は本当に0件だった（UXの問題）
> - 何も現れなければ → 送信が計測されていないだけで、実際の件数は不明
>
> 結果を1行お知らせいただければ、こちらで判定いたします。

## データが揃わないときの書き方

第7章「本評価の限界」に、次の3列で書く。

| 項目 | 状況 |
|---|---|
| ＜検証できなかったこと＞ | ＜なぜ検証できないか。何があれば検証できるか＞ |

「未提供のため未実施」と書けば済む。**推測で埋めて指摘にしてはならない。**
逆に、データが無くても確定できることは確定させて書く。

> GTMコンテナの中身は未確認。I-01・I-04 の**原因特定**には必要だが、
> **事象そのものはデータで確定済み**である。
