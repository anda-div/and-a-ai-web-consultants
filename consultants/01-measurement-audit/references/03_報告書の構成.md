# 報告書の構成

## 全体の章立て

| 章 | 内容 | 性格 |
|---|---|---|
| 表紙 | 評価対象／制作元／宛先／評価の目的／検証に用いたデータ／作成日／本書の位置づけ | ― |
| 本書の構成・読み方 | 章の一覧と、時間別の読み方（5分版／修正作業時／妥当性を確かめたいとき） | ― |
| **第0章 総合判定** | 結論の1枚集約。確定した指摘の一覧表。評価できる点 | 結論 |
| **第1章 検証の範囲と方法** | どのデータで何を検証したか。検証度（◎全面／○部分／×未実施） | 手続 |
| **第2章 確定した指摘事項（F-01〜）** | 本書の中心。修正が必要な点 | 指摘 |
| **第3章 レポートを強化できる発見（D-01〜）** | 指摘ではなく、次版で使える材料 | 還元 |
| **第4章 数値突合表** | レポート記載値 vs 独立再集計値 | 証拠 |
| **第5章 改善提案の妥当性判定** | 提案それぞれの評価（支持／根拠を差し替え／再検討） | 判定 |
| **第6章 計測基盤の修正** | レポートとは別件だが先に着手すべきこと。優先度順 | 処方 |
| **第7章 未検証範囲と次のアクション** | 本評価の限界の明示。追加でほしいデータ（優先順位つき） | 限界 |
| **第8章 本評価における訂正記録** | 評価側が撤回・訂正した項目の全件開示 | 誠実性 |
| 付録 | 指摘の根拠となる明細データ | 証拠 |

---

## 各章の書き方

### 表紙

必ず入れる項目：

| 項目 | 内容 |
|---|---|
| 評価対象 | ファイル名（版まで）／対象サイト／対象期間 |
| 対象レポート制作 | 制作元 |
| 対象レポート宛先 | 宛先 |
| 評価の目的 | ① レポートの品質監査 ② 結論そのものの独立検証 ③ クライアント視点でのレビュー |
| 検証に用いたデータ | エクスポートの種類と本数、管理画面の確認、実サイトの確認日 |
| 作成日 | |
| 本書の位置づけ | 中間報告なのか確定版なのか。改訂であれば何を反映したか |

### 第0章 総合判定

構成は必ずこの順：

1. **結論**（3〜6段落）
   - どの章が書き直しを要するか
   - **数値の転記精度についての評価を先に述べる**（誤りが無いなら「無い」と明記する）
   - 問題の本質を1文で言い切る
     （例：「処方箋は概ね当たっているが、診断書の数字が違う」）
   - 提案を撤回する必要があるのかどうかを明示する
2. **確定した指摘の一覧表**：`# / 重要度 / 指摘 / 影響範囲` の4列
3. **評価できる点**：箇条書き。おざなりにしない（`02_指摘の書式と重要度.md` 参照）

### 第1章 検証の範囲と方法

- **1-1 用いたデータ**：種類・期間・行数まで書く。
  複数のエクスポート間で総数が一致していることを確認したら、その旨も書く
  （データ自体の整合性に問題がないことの証明になる）。
- **1-2 検証できた範囲**：対象の章ごとに `◎全面 / ○部分 / × 未実施` と理由。
  未実施は必ず理由を書き、第7章と対応させる。
- **1-3 検証の進め方**：反証の手続きを書く。
  「指摘を確定させる前に、必ず『別の説明が成り立たないか』を検討している」ことと、
  仮説が否定された場合は第8章に記録することを明記する。

### 第2章 確定した指摘事項

`02_指摘の書式と重要度.md` の書式に従う。重要度の高い順に並べる。

### 第3章 レポートを強化できる発見

冒頭に「本章は指摘ではありません」と明記する。

### 第4章 数値突合表

`gt_reconcile.py` の出力をそのまま使える。最後に**転記精度についての総評**を置く。
全項目一致だった場合は、それをはっきり書く。

> 本評価の指摘は「数え間違い」ではなく、
> 「壊れた計測器の目盛りを、壊れていることに気づかないまま読んだ」ことに集中しています。

### 第5章 改善提案の妥当性判定

`# / 提案 / 判定 / 理由` の4列の表。判定は3段階（支持／支持（根拠を差し替え）／再検討が必要）。

続けて次の2節を置く：

- **5-1 着手順について**：レポートが示す着手順に、抜けている前提が無いか。
  多くの場合「計測基盤の修正を先に（または同時に）やる必要がある」が抜けている。
- **5-2 効果検証の設計について**：ABテストが成立する母数か。
  月あたりのCV件数が2桁に満たない場合、ABテストは統計的に成立しない。
  その場合は「①計測基盤の修正 → ②1〜2か月のベースライン取得 → ③施策実施 → ④前後比較」を提案し、
  マイクロコンバージョンを補助指標に置く。

### 第6章 計測基盤の修正

`# / 内容 / 工数 / 根拠(指摘番号)` の表。**優先度順**に並べる。
続けて「あわせて確認すべきこと」（広告の最適化対象、他プロパティの同一設定、BigQueryエクスポート等）。

### 第7章 未検証範囲と次のアクション

- **7-1 本評価の限界**：`項目 / 状況` の表。「取得不可」「未提供」「未確認」を正直に書く。
- **7-2 ＜最重要の未確定事項＞を確定させる方法**：手順と所要時間、結果の読み方（分岐まで）。
- **7-3 追加でいただければ検証できるもの**：`優先 / いただくもの / それで確定すること` の表。

### 第8章 本評価における訂正記録

冒頭に一文：

> 第三者評価の信頼性は、評価側が自分の誤りをどう扱うかにも表れます。
> 本評価の過程で撤回・訂正した項目を、すべて開示します。

`# / 当初の見解 / 検証結果 / 対応` の表。**全件。**

### 付録

指摘の根拠となる明細（内訳の全件、分類とその確度）。
分類に推定が混ざる場合は、どこまでが確実でどこからが推定かを明示する。

## 末尾

> 本書に関するお問い合わせ
> 各指摘には「ご自身で確認する方法」を記載しています。判定に疑義がある場合は、
> その手順でご確認のうえお知らせください。データにもとづく反証があれば、第8章と同様に訂正いたします。

この一文があると、報告書は「判決」ではなく「議論の出発点」になる。
