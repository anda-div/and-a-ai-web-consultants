# 検査カタログ ― 計測器そのものの健全性検査（I-01〜I-10）

レポートの数値が正しく転記されていても、その数値を produce した計測器が壊れていれば、
結論は成立しない。本カタログは「計測器の故障」を検出するための検査項目である。

各項目には **判定の閾値**・**なぜその閾値なのか**・**確定に必要な追加確認**を書いている。
閾値を超えたことは「疑い」であって「確定」ではない。確定には `04_対抗仮説カタログ.md` を通すこと。

---

## I-01 page_view の二重発火

### 何を見るか

ページ別の「表示回数 ÷ ユーザー数（1ユーザーあたりのビュー数）」の分布と、表示回数の偶奇。

### 判定の閾値

| 指標 | 正常な範囲 | 疑いあり |
|---|---|---|
| 1ユーザーあたりビュー数の中央値 | 1.0〜1.4 | **1.8以上** |
| ちょうど2.00のページの割合 | ごく少数 | **全体の25%以上** |
| 表示回数が偶数のページの割合 | 約50% | **70%以上** |

### なぜこの閾値なのか

- 通常のサイトでは、大多数のページが「1人が1回だけ見る」ため、1ユーザーあたりのビュー数は
  1.0〜1.4に収まる。互いに無関係な低トラフィックページ（利用規約・個別商品ページなど）が
  軒並み正確に 2.00 になるのは、人間の行動としては起こらない。
- すべての閲覧が2回ずつ記録されるなら、表示回数は必ず偶数になる。
  二重発火が無ければ偶数・奇数はほぼ半々になる。自然なデータでは
  「1人が1回だけ見た＝PV 1」という**奇数が最頻値**になるため、
  偶数のほうが多いという観測は、それ自体が異常である。
- 偶数への偏りは二項分布で評価できる。例：112ページ中92ページが偶数になる確率は
  約 6,270億分の1（p ≈ 1.6e-12）。

### 補強証拠（あると確定に近づく）

1. **2.00を下回るページの検算**：比が2.00未満のページはすべて表示回数が奇数で、
   「2倍なら得られたはずの数」との差（欠落数）が1に揃う。
   自然な閲覧行動なら、欠落数が揃って1になる理由がない。
2. **規模帯別の偶奇**：例外が稀（閲覧100回に1〜2回程度）であれば、
   PVが小さいページほど偶数率が高く、PVが大きいページほど下がる。
3. **1人しか訪れていないページ**：PV=1 がほとんど存在せず PV=2 が大半になる。

### 確定後の影響範囲

| 指標 | 状態 |
|---|---|
| PV・遷移PV | 実質は約半分 |
| エンゲージメント率 | **無効**。エンゲージセッションは「10秒超の滞在 **または** 2ページ以上の閲覧 **または** キーイベント発生」で判定されるため、page_view が2回発火すると1ページしか見ていないセッションでも自動的に「2ページ以上」を満たす |
| 直帰率 | **無効**（エンゲージメント率の裏返し） |
| セッション・ユーザー | 影響なし |
| ファネルのユーザー数 | 影響なし |
| Search Console の全数値 | 影響なし（GA4と無関係） |
| ページ間の相対的な大小関係・構成比・順位 | 影響なし（全ページが等しく2倍のため） |

最後の行が実務上いちばん重要。**構造的な結論（どのページがハブか、どこが強いか）は生き残る。**
崩れるのは絶対値と、絶対値から導いた「質が高い」という評価だけである。

### 原因の切り分け

`session_start` が1セッションあたり1.00、`first_visit` がユーザーあたり1.0前後で正常なら、
タグが2セット入っているのではなく、**gtag.js が1つ読み込まれ config の呼び出しが2回ある**状態。
（gtag.js はセッション開始を1回しか送らないが、config が呼ばれるたびに page_view を送る）

候補：GTMで「GA4設定タグ」と「GA4イベントタグ（page_view）」を両方 All Pages で発火させている／
テーマに gtag が直書きされていてGTMからも送っている／CMSのチャネルアプリと併用している。

### ご自身で確認する方法

- （1分）GA4「レポート → エンゲージメント → ページとスクリーン」で1ページあたりの行数を250にし、
  「アクティブユーザーあたりのビュー」で昇順に並べ替える。正常なら1.0〜1.3が並ぶ。
- （30秒・決定的）GA4「レポート → リアルタイム」を開いた状態で、別のタブでページを1回だけ開く。
  「イベント数（イベント名別）」で page_view が2カウントされれば確定。

## I-02 イベント種別ごとの1人あたり件数

### 何を見るか

ページ読み込みで**自動発火する**イベントと、**ユーザーの操作で起きる**イベントの、1人あたり件数の対比。

| 種別 | イベント例 |
|---|---|
| 自動発火 | page_view, first_visit, session_start, user_engagement, scroll |
| 操作起因 | click, form_start, form_submit, add_to_cart, begin_checkout, purchase, view_item |

### 判定

- 操作起因イベントが正常（1.0〜1.5程度）で、**page_view だけが2.00前後に固定** → config の重複（I-01）
- 全イベントが一様に倍 → 計測タグが2セット（I-10）
- どちらでもない → 二重発火以外の原因を疑う

## I-03 キーイベント（コンバージョン）の肥大

### 何を見るか

キーイベント数の合計とセッション数の比。キーイベントに指定されているイベント名。

### 判定の閾値

**キーイベント数がセッション数を超えていたら、まず設定ミス。**

### なぜ問題か

キーイベントの指定は、レポートの「キーイベント数」だけでなく、
**Google広告の入札最適化の目標・オーディエンスの条件・アトリビューション**にも同時に効く。
全ページ・全訪問で発火する page_view を成果にすると、これらがすべて
「ページを開いた人」を追いかけ始める。クリックして開いてすぐ帰る人を集める方向に配信が寄る。

これは**レポートの品質とは別に、現在お金が流れている問題**である。優先度を上げて報告すること。

### 通常キーイベントにしてはいけないもの

`page_view` / `first_visit` / `scroll` / `click` / `user_engagement` / `view_item` /
`view_search_results`

### 「サンクスページの表示をCVにしたい」という要望への正しい答え

page_view のトグルをONにするのではなく、GA4の「管理 → イベント → イベントを作成」で
`page_location` が特定URLを含む `page_view` を条件とする新しいイベント（例：`generate_lead`）を作り、
そちらをキーイベントにする。

## I-04 設計されているのに0件のCVイベント

### 何を見るか

イベント名がCVらしい（`cv01_`, `tel_tap`, `contact_`, `..._完了`, `..._送信` 等）のに、
対象期間の発生が0件のイベント。GA4管理画面で「ストリーム データが検出されませんでした」の状態。

### なぜ重大か

**「成果が無かった」のか「計測できていなかった」のかで、打ち手が正反対になる。**
この2つを区別しないまま「CVが0件です」と書いてはならない。

### よくある原因

- GTM側が別名で送信していて、GA4側が別の名前を待っている（`tel_tap` と `tell_tap` など）。
  名称自体は動作に影響しないが、**送信側と待ち受け側の綴りが違えば永久に0件になる**。
- 作成イベントの条件が、連鎖して0件になっている（元イベントが0件なら作成イベントも0件）。
- タグは発火しているがトリガー条件が実際のDOMと合っていない。

### 確定方法

GTMコンテナをエクスポート（JSON）して、送信側のイベント名を確認する。

## I-05 ファネル各段の母集団一致

### 何を見るか

ファネルの各段の数字が、**すべて同じ1ページ（同じ母集団）**から取られているか。

### なぜ壊れるか

GA4には数字の出どころが2種類ある。

| レポート | 返すもの |
|---|---|
| 「ページとスクリーン」 | ページごとの数値 |
| 「イベント」 | **サイト全体の合計** |

`form_start` / `form_submit` は後者にしか出てこない。ページ別に分解しない限り
「どのページで起きたか」は分からない。

さらに、拡張計測機能の `form_start` は HTML の `<form>` 要素への最初の操作を検知して発火し、
**フォームの種類を区別しない**。問い合わせフォームも、商品ページの「カートに追加」も、
検索窓も、フッターのメルマガ登録欄も、決済画面の入力欄も、すべて同じ `form_start` になる。

### 何が起きるか

「ページ到達 381 → フォーム開始 37」と並べると、37人には**そのページを訪れていない人**が含まれる。
上の集団に含まれない人が下の段に現れるため、37 ÷ 381 という割り算そのものが成立しない。

### 検出方法

`eventName × pagePath` で分解し、サイト全体の値に対する当該ページの占有率を見る。
占有率が9割を切り、複数ページに分散していれば、その値はページ単体の数ではない。

### 修正の方向

ファネルの各段を、すべて同じ1ページの数字に統一して描き直す。
中間段として `scroll`（縦90%到達＝CTA位置への到達）を挟むと、
「到達したが下まで見ていない」層と「下まで見たが書き始めない」層を分離できる。

## I-06 対象範囲の外への流出（外部ドメイン）

### 何を見るか

`click`（拡張計測機能の離脱クリック）の分布。リンク先ドメイン（`linkDomain`）。

### なぜ見落とされるか

GA4の「ページ間の遷移」は**サイト内のページからページへの移動しか返さない**。
外部ドメインへ出ていった人は遷移先が存在しないため、表に現れない。
「ページの出口」を内部遷移だけで集計すると、最大の出口を丸ごと見落とす。

### 判定

- `click` の総数の**50%以上が1ページに集中**していたら、そのページの主要CTAのリンク先が
  外部ドメインである可能性が高い。実サイトでリンク先を確認すること。
- 行き先が**自社の別ドメイン**（EC・予約サイト等）の場合、そのページは
  「CVに繋がっていない」のではなく「成果が別ドメインで計上されている」。
  結論が反転するため、影響は大きい。

### 確定方法

GA4探索でディメンション「リンク ドメイン」を追加し、イベント名 `click` で絞る。

## I-07 内部トラフィックの混入

### 何を見るか

- 一般ユーザーが到達できないURL（`_preview`, `/admin`, `staging` 等）
- 1ユーザーあたりの閲覧回数が極端なページ（**8回以上**を目安）
- 平均エンゲージメント時間が極端に長いページ（10分超など）

### 影響

全体に占める比率は小さくても、ユーザー数・平均エンゲージメント時間・1人あたり閲覧数に影響する。
内部トラフィック除外（IPフィルタ）が機能していない可能性が高い。

## I-08 個人を特定しうる情報の混入

### 何を見るか

ページタイトル・ページパス・クエリ文字列に、氏名・メールアドレス・電話番号が含まれていないか。
（例：「〇〇様、ありがとうございます。」という注文ステータスページのタイトル）

### なぜ報告するか

Googleアナリティクスの利用規約は、個人を特定できる情報の送信を禁止している。
姓のみであれば直ちに重大な違反となるかは判断が分かれるが、
**意図せず個人情報が送信されている状態であること**は確かである。
レポートの品質とは別問題だが、計測基盤の点検事項として必ず共有する。

### 対処

GA4のデータストリーム設定でページタイトルを書き換えるか、GTMでフィルタする。

## I-09 Search Console のクエリ被覆率

### 何を見るか

クエリ別データの合計（クリック・表示）と、全体値の差。

### 判定

クエリ別に見えているのが全体の95%未満なら、匿名化クエリの影響を明記すべき。
実務では**クリックの3割前後しか見えていない**ことが珍しくない。

### なぜ問題か

「指名検索が中心」「非指名を取りこぼしている」という結論は、
**見えている範囲の中での構成比**にすぎない。実際の指名／非指名比率は、この数字からは確定できない。

### 修正の方向

「クエリ別に見えているのはクリックの約N%で、残りは匿名化されている」旨を明記し、
断定を「見えている範囲では」に改める。

## I-10 計測タグの重複（計測が2セット）

### 何を見るか

`session_start` の1人あたり件数、`first_visit` の1人あたり件数。

### 判定

- `session_start` が1人あたり1.9以上 → タグが2セット入っている疑い
- `first_visit` が1人あたり1.5以上 → 同上

### なぜ重要か

I-01（config の重複）と I-10（タグが2セット）は、**直すべき場所が違う**。
また I-10 の場合はセッション数・ユーザー数まで信用できなくなるため、
影響範囲が I-01 より大きい。この2つを混同しない。

## 検査結果の書き方（共通）

- 閾値を超えなかった項目も **「所見なし」として報告書に書く**。
  何を見て何が無かったのかが分からない報告書は、検査していないのと区別がつかない。
- 検査できなかった項目は「未検査」とし、**何があれば検査できるか**を書く。
- 疑いの段階のものは「確定した指摘」に混ぜない。第7章（未検証範囲）に置く。
