# 毎月の書き起こしは、基本的に自動で進む

月次レポートで人が最も時間を使うのは「今月は何を論点にするか」を考え、
所見・提案・要約を書き起こす工程です。ここが毎月の負担になり、
数か月で「もう出すことが無い」という状態になります。

この文書は、**その工程を CLI AI が自走し、人は「承認」か「追加依頼」だけをする**運用の方法です。
別業種の月次レポート案件で確立し、4か月連続で納品している方式を、固有名詞を外して書いています。

---

## 0. 結論

| | 誰がやるか |
|---|---|
| データを所定の場所に置く | 人 |
| 使用済みの切り口を棚卸しする | **AI** |
| 今月のデータが「どこで動いたか」を読む | **AI** |
| **今月の切り口を決めて、宣言する** | **AI** |
| 競合・ヒートマップ対象・提案の型を切り口に合わせて選ぶ | **AI** |
| 所見・提案・要約・エグゼクティブサマリーを**全文**書き起こす | **AI** |
| 生成したレポートを画像化する | 人（ツール） |
| 読んで、**承認する**か、**直してほしい点を伝える** | 人 |
| 指摘を反映し、台帳を更新する | **AI** |

人が白紙に向かう工程はありません。**人の仕事は「考え出す」から「読んで決める」に変わります。**

---

## 1. 実績（この方式が実際に回った記録）

別業種の月次レポート案件、2026年8月納品分（53スライド）。

| | |
|---|---|
| 制作期間 | 2日（8/4 準備・8/7 仕上げ） |
| 担当者の発言回数 | **34回** |
| うち「データを置いた」「ファイルを閉じた」等の連絡 | 約半数 |
| うち 2択への決定 | 2回（構成の選択、確定の宣言） |
| うち 目視後の修正依頼 | **1通**（スライド11か所） |
| 担当者が切り口を指定した回数 | **0回** |

切り口は AI がデータを読み、自分で確定して宣言しています。

> 「切り口が確定しました。**「量から質へ」**で進めます。競合URLを確認してから、キャプチャ取得に進みます。」

担当者が書いたのは、その前の「GA4のデータを見た後に、今月の切り口を考えてください」の1行だけです。

## 2. なぜ「同じ文章が並ぶレポート」にならないのか

自動化すれば毎月そっくり同じ文章になる、という懸念は正しいです。
それを防いでいるのは AI の賢さではなく、**3つの仕組み**です。

### 仕組み1 — 切り口を決める前に、必ず台帳を読む

`_ledger/angles_history.json` に、月ごとの記録が残ります。

| 記録するもの | 例 |
|---|---|
| 切り口（1行の題） | 「量から質へ ── 流入が減った月に、成果は伸びた」 |
| 主指標 | セッション -2.9% ／ 直帰率 -1.75pt ／ 主要CV +20.6% |
| 特集の視点 | ①量は減った、質は上がった ②下流CVが回復 ③フォームの入口で半分落ちる |
| 競合 | A社／B社／C社 ＝「同じ層に比較検討される隣接カテゴリ」という系統 |
| ヒートマップ対象 | 会員ページ／申込ページ／安心材料のページ |
| ヒューリスティック対象 | 会員ページ／申込ページ／安心材料のページ（3か月続いた「TOP＋申込」から変更） |
| 提案の型 | 入口の新規優先化／不安解消の文脈CTA／相談窓口の交通整理 |

そして台帳から自動で**「もう使ったリスト」**が5分類で出ます。

| 分類 | 内容 |
|---|---|
| 切り口の軸 | TOP→申込導線／申込完了率の歩留まり／回遊→申込の橋渡し／量から質へ … |
| 提案の型 | FV/ページ内CTA新設（3回）／申込完了後のネクストステップ／相談導線再設計（2回）… |
| 競合の系統 | 同業の直接競合／サブスク・リース型／セルフ申込が強い他業界／隣接カテゴリ |
| ヒートマップ対象 | TOP／申込／商品詳細3種／会員ページ／安心材料のページ |
| ヒューリスティック対象 | TOP／申込／会員ページ／安心材料のページ |

**「CTA新設系の提案は3か月で3回。提案の『型』も替える必要がある」** —
これは AI が台帳を読んで自分で書いた注記です。台帳が無ければ気づけません。

### 仕組み2 — 切り口は「データが動いた場所」から選ぶ

候補は前もって並べておきます（切り口カタログ）。しかし**選ぶのは、当月のデータを見てから**です。

> 7月は前月と真逆の構図です。流入は減ったのに、質も成果も全面回復した月です。
> 6月（量は増えたが下流が細った）と真逆で、対比として非常にきれいです。

データ根拠が立たない候補は採りません。「今月はこれが動いた」が切り口になるので、
データが違えば切り口も違います。**新しさはひらめきではなく、データとローテーションが生みます。**

### 仕組み3 — 宣言のときに「非重複」を明示する

AI が切り口を宣言するとき、直近3か月との非重複を根拠つきで書きます。

> ※ 直近3ヶ月と非重複（第4条）:
>  4月データ=TOP→申込導線／5月データ=申込導線の総点検／6月データ=回遊→申込の橋渡し。
>  競合も 同業勢／サブスク・リース勢／他業界のセルフ申込勢 とは別カテゴリ。
>  第3章の分析対象も3か月連続の「TOP＋申込」から変更する。

これが本文の先頭に書かれているので、人は「重複していないか」を確かめる必要がありません。
**確かめる作業そのものが、AI の側に移っています。**

## 3. 人がすること — 承認か、追加依頼か

AI が書いたものを画像で読み、次のどちらかをします。

### 承認

短い一言で足ります。実例：

> 「このまま8枚を冒頭に置くで、決定します」
> 「了解しました。」
> 「2 → 1 → 3 の順にお願いします。」

### 追加依頼

読んで気になったところを、スライド番号つきで書きます。実例（1通・11か所）：

> スライド3　文章だと分かりにくいので、表で表現してください。
> スライド8　報告会に開発エンジニアが出席します。IF-THEN で詳細な解説ページを追加できませんか。
> スライド27　「相談窓口4系統」に（フォーム／電話／オンライン相談／チャット）を補ってください。
> スライド35　文章だけだと分かりにくいので、1項目1ページで4社分の画面キャプチャを並べてください。

**「こう書いてほしい」と原稿を書く必要はありません。「分かりにくい」「根拠を足して」「表にして」で足ります。**
AI が直して、再び画像で確認します。

### AI が判断を求めてくる場面

AI は迷ったとき、**推奨つきの2択**で聞いてきます。

> 1. このまま8枚を冒頭に置く
> 2. 冒頭4枚＋巻末APPENDIX 4枚に組み替える（私のおすすめ）
>
> 2をおすすめする理由は「開示すべき3件はすべて冒頭に残るので誠実さは損なわれない」
> 「今月は良い月なので、その成果が8枚の後ろに埋もれるのはもったいない」の2点です。

人は番号を答えます。AI は推奨と違う答えでも、そのまま実行します。

## 4. AI が自走できるための、人の側の約束

自走は、人が次を守ると成立します。

| 約束 | 理由 |
|---|---|
| **データを所定の場所に置く**（GA4の書き出し、ヒートマップ） | ログインが必要な管理画面は人しか触れない |
| **事実の質問には答える**（「チャット窓は7月に導入されたか」等） | サイト側の事情は AI には分からない |
| **判断を求められたら番号で答える** | AI は決めきれない所だけを聞いてくる |
| **画像化して見る**（全ページを PNG に） | AI は自分で描画できないため、描画結果は人が渡す |
| **直してほしい点はスライド番号で伝える** | 原稿を書く必要はない |

これ以外の工程で、人が手を動かす場面はありません。

## 5. 何が自動で、何が人か（1枚で）

```text
人    データを置く
      ↓
AI    台帳を読む → データが動いた所を読む → 切り口を確定して宣言 → 非重複を明示
      ↓
AI    競合・ヒートマップ対象・提案の型を切り口に合わせて選ぶ
      ↓
AI    所見・提案・要約・サマリーを全文書き起こす → PPTX を生成 → 体裁を機械で測る
      ↓
人    画像化して読む
      ↓
人    「承認」 or 「スライド◯：△△にしてください」
      ↓
AI    反映 → 台帳に当月分を追記 → 納品形式で保存
```

## 6. 導入時の注意

- **最初の1〜2か月は、人の側の「追加依頼」が多くなります。** これは AI がクライアントのトーンや禁止事項を
  まだ知らないためで、指摘はプロジェクトの `CLAUDE.md` に蓄積します。3か月目から減ります。
- **却下された提案を記録すること。** 「相談を会員登録なしでもできるようにする」は過去に却下されたのに、
  AI が再提案してしまった実例があります。台帳に理由つきで残せば再発しません。
- **AI の推奨に従う義務はありません。** 人が別の判断をしたら、AI はそれに従います。
  ただし AI は理由を述べます。それを読んで決めるのが人の仕事です。
