# JOB 07｜レポート・効果検証

![レポート・効果検証コンサルタント](assets/character.png)

7人の成果を、意思決定しやすいレポートへまとめ、納品前の独立QAと施策後のBefore/After検証を行うAIです。制作とチェックを分離し、数字・根拠・体裁を追跡します。

## このJOBが行うこと

- 課題・施策・根拠のレポート構成
- **PowerPointレポートの生成**（テンプレートの体裁を保ったまま組み立てる）
- PowerPointからの全文・数値抽出
- 全スライドのレンダリング確認
- 数値トレーサビリティと回帰チェック
- Before/Afterの効果検証と次の一手

## 入力

- JOB 01〜06の成果物
- PPTXテンプレートまたは既存レポート
- 効果検証用の前後データ

## 出力

- PPTXまたはレポート原稿
- 納品前チェック報告
- 効果検証報告
- 次月の継続観測項目

## レポート生成の部品

レポートの体裁は案件ごとに違います。そこで「作図の部品」と「案件固有の値」を分けています。

| ファイル | 役割 |
|---|---|
| `scripts/report_config.py` | `defaults/` と `_config/` を重ねて読む。値は一切持たない |
| `scripts/deck_kit.py` | 作図の最小部品。配色・レイアウト名・座標はConfigから受け取る |
| `scripts/site_report_kit.py` | ページの型6種。`deck_kit` の上に載せる |
| `scripts/inspect_template.py` | テンプレートを解析し、`branding.json` に書く値を出力 |
| `scripts/make_default_templates.py` | 既定テンプレート（16:9 / 4:3）を生成 |
| `scripts/ledger.py` | 提案台帳。過去の提案の照会・状態の更新 |
| `scripts/build_briefing.py` | 月初ブリーフィングを作る（台帳＋切り口＋指標） |
| `scripts/check_layout.py` | 生成したPPTXの体裁を測る（重なり・枠外・下の空き・画像） |
| `scripts/check_stray_files.py` | 紛れ込んだ空ファイルを見つける（納品前チェック） |
| `defaults/` | 汎用の既定値。章立て・体裁ルール・競合の方法論・ページ座標・切り口カタログ・台帳のルール |
| `config.example/` | Configのひな形（架空値）。`_config` としてコピーして使う |

### ページの型（`site_report_kit`）

実績レポートで繰り返し使われる型をまとめたものです。

| 型 | 関数 | 使いどころ |
|---|---|---|
| A | `two_col_tables` | 表を左右に並べ、下に解釈。表1つなら全幅に広がる |
| B | `kpi_and_chart` / `two_charts` | KPIカード＋グラフ＋右に解釈／グラフ左右 |
| C | `boxes` | 箱だけ（サマリー・まとめ）。カラム数は可変 |
| D | `capture_right` / `capture_left` | 左箱＋右キャプチャ／左キャプチャ＋右箱 |
| E | `heatmap` | ヒートマップを分割して横並び |
| F | `flow_diagram` | 箱と矢印で導線を図示（ファネルの離脱など） |

`competitor_pages`（1社1枚で競合章を作る）と `glossary`（用語集の自動分割）も含みます。

### 提案が枯渇しないようにする

毎月同じサイトを見ていると「もう出すことが無い」という状態になります。
発想力ではなく、**憶えていられない・角度が固定される・結果を確かめる前に次の月が来る**の3つが原因です。

```bash
python scripts/build_briefing.py 2026-07   # 月初に1回。白紙から考え始めない
```

| 節 | 誰が用意するか |
|---|---|
| 台帳の状況（未実装・却下）／効果を検証すべき提案／今月使える切り口／主要指標 | 機械 |
| 提案候補10本 | AI（依頼文が同梱される） |
| どれを載せるか、言い切り方、相手への配慮 | 人 |

**人が白紙に向かう工程を無くすのが狙いです。**

### 毎月の書き起こしは、基本的に自動で進む

切り口・所見・提案・要約・エグゼクティブサマリーは **AI が全文を書き起こします。**
人がすることは **「承認」か「追加依頼」の2つだけ**です。

- 切り口は **候補を並べて人に選ばせません。** AI が台帳の「もう使ったリスト」を読み、
  当月データが動いた場所から **1本を確定して宣言**します（根拠＋直近3か月との非重複を添えて）。
- 迷う点だけ、**推奨つきの2択**で聞いてきます。それ以外は聞かずに進みます。
- 追加依頼は原稿でなくて構いません。「スライド12を表にして」「スライド20は言い過ぎ、根拠を足して」で足ります。

別業種の月次レポート案件で確立し、4か月連続で納品している方式です
（53枚を2日、担当者の発言34回、切り口の指定0回）。
詳しくは [MONTHLY_ANGLE_METHOD.md](MONTHLY_ANGLE_METHOD.md) を参照してください。

### 実装された提案を追いかける

出した提案が実装されたのかどうか分からないまま消えていく、というのは広く起きています。
これは**組織の問題（決まらない）**と**方法の問題（測れない）**が混ざっているためです。混ぜたまま解こうとすると、実装されなかった提案のための立派な効果測定設計ができあがります。

```bash
python scripts/ledger.py --low-cost                    # まとめて1回の発注にできる候補
python scripts/ledger.py --order-sheet --vendor 制作    # そのまま渡せる発注依頼書
python scripts/ledger.py --status-sheet 2026-09        # 打ち合わせ用の確認シート
python scripts/ledger.py --revisit-due 2026-12         # 再検討の期日が来た保留
```

要点は3つです。

- **「自分で直せば無料」を前提にしない。** テキスト1文字の修正でも外注する運用は珍しくありません。責任の所在をはっきりさせるための判断であって、費用の問題ではないためです。外注を前提に**費用帯**で分け、低コスト帯は**まとめて1回の発注**にします。金額ではなく手続きの回数が障害になっている場合があります。
- **状態を尋ねず、書いて訂正してもらう。** 「あれはどうなりましたか」は一方向の催促になります。空欄を埋めるより、書かれた内容を直すほうが答えやすい。
- **効く指標は「局所の比率」にする。** 分子と分母が同じ段階にあれば、広告のロジック変更・競合の動き・季節性は両方に等しくかかるため、比率は環境変化に残ります。ただし**売上への寄与は証明できません。**証明ではなく、次にどこへ投資するかの判断材料として扱います。

詳しくは [PROPOSAL_LEDGER.md](PROPOSAL_LEDGER.md) を参照してください。

### 生成したら測る

```bash
python scripts/check_layout.py output/report.pptx
```

スライドの座標はファイルの中に正確に入っています。**測れることは測ってしまい、
人の目は「文章として正しいか」に使います。**

| 見るもの | 判定 |
|---|---|
| 重なり | 内容どうしが重なっていないか。画像の内側に収まる注記は対象外（Before/Afterの吹き出しなど） |
| 枠外 | 図形が用紙からはみ出していないか |
| 画像のゆがみ | 元の縦横比のまま置かれているか（2%以上ずれたら指摘） |
| 細い画像 | 縦長すぎて読めなくなっていないか。分割して横並びにしているページは対象外 |
| 下の空き | 内容の下端と要約枠の間（既定 3cm 以上で指摘） |
| 文字サイズ | 箱の中の本文が既定 6pt を下回っていないか。注記帯とキャプションは対象外 |
| 制御文字 | パスのエスケープ漏れで `_x000D_` などが混ざっていないか（描画するまで見えない） |

要対応が1件でもあれば終了コード 1 を返すので、生成の直後に続けて実行できます。

**意図した表現は指摘しません。**
完全に内側に収まる重なり（見出し帯の上のラベル、キャプチャの上の注記）、
分割して横並びにした画像、切り抜いた画像、注記帯の小さな文字。
テキストボックスは枠ではなく**文字の占める範囲**で見ます。

ゆるめすぎれば何も報告しない検査になるため、
`tests/test_check_layout.py` がわざと壊したファイルを作り、
**6種類の欠陥それぞれを拾えること**と、
**意図した表現を指摘しないこと**の両方を毎回確かめます。

**この検査で見つからないもの**は、そのまま人が見る対象です。
解説と画面が食い違っていないか、数値の意味が正しいか、言い過ぎていないか、宛先・日付が正しいか。

### ページの下半分を空けない

内容が上半分で終わり、下が白いままのページは「作りかけ」に見えます。
生成後に、各ページの内容の下端と要約枠の間を測り、**3cm以上空いているページを潰します**。

空きを埋める手段は次の順で選びます。

1. **行を増やす** … 表の件数を増やす（上位6件→14件など）。データがあるのに見せていないなら、まずこれ。
2. **要素を大きくする** … `kpi_and_chart(chart_h=...)` でグラフを高くする。行高を上げて読みやすくする。
3. **解釈を足す** … `two_col_tables(fill=True)` で解釈の箱を要約枠の直前まで伸ばし、**中身も足す**。

`fill=True` は箱を伸ばすだけです。**空の箱を大きくしても読み手には何も伝わりません。**
伸ばしたぶんは、その表から読み取れることで埋めてください。

### 設定は「既定 ＋ 上書き」

`_config/` は納品後、利用者のPC上に置かれます。提供者が直接は直せません。
そこで**汎用の既定値は `defaults/`（このリポジトリ側）に置き**、
`_config/` には「その案件でしか決められないこと」だけを書きます。

改善を見つけたときは、`defaults/` の差し替えを案内するだけで全利用者へ届きます。

| `_config/` に置く | `defaults/` に置く |
|---|---|
| 会社名、計測ID、URL、対象期間 | 章立て、ページ型の座標、体裁ルール |
| テンプレートのパスと実測座標 | 競合比較の方法論、シート名 |
| 競合の具体名、固有名詞リスト | 出力ファイル名の形式 |

`deck_kit` が提供するもの:

- ページの型 … `content`（見出し＋サブタイトル）`section`（章扉）`title_slide`
- 要素 … `box`（自動高さ・余白ルール付き）`table` `chart` `summary` `note`
- 日本語の体裁 … 禁則処理、言語指定、本文の最小サイズの強制
- レイアウト補助 … 箱の高さ揃え、必要高さの見積り、収まるフォントサイズの算出
- ヒートマップ … 縦長画像の分割と横並び配置
- 品質チェック … 本文最小サイズに収まらない箱の一覧（`report_overflow`）

```python
from pptx import Presentation
from report_config import load
from deck_kit import build_kit

cfg = load()                        # 直近の親にある _config/ を探す
prs = Presentation(cfg.template())
K   = build_kit(prs, cfg)

s = K.content("流入分析", "どこから来た人が成果に近いか")
K.table(s, K.LEFT, 2.2, K.WIDTH, [["チャネル", "セッション"], ["自然検索", "1,234"]])
K.summary(s, "自然検索が最大の入口です。")
K.note(s, "出所：GA4（対象期間）")
K.report_overflow()                 # 文章を短くすべき箱を一覧表示
prs.save("output/report.pptx")
```

## テンプレートの確認（最初に必ず行う）

体裁はあとから変えると手戻りが非常に大きくなります。
生成を始める前に、テンプレートの有無と用紙比率を確定させてください。
判断のながれと確認の文面は [`TEMPLATE_POLICY.md`](TEMPLATE_POLICY.md) にあります。

```text
テンプレートは提供されているか？
├─ YES → 解析して100%準拠で生成する
└─ NO  → 「本当に無いか」を確認する
          ├─ 実は在った → 解析へ
          └─ 本当に無い → 用紙比率（16:9 / 4:3）を確認して既定テンプレートで生成
```

この確認を飛ばしてよい場合はありません。2回目以降も毎回確認します。

## 文章は毎回書き起こす

`deck_kit` が持つのは「描き方」であって「書く内容」ではありません。
本文・所見・提案は、その月のデータを見てCLI AIが書き起こします。
先月の文章を使い回さないでください（`docs/WORKFLOW.md` の「毎月の新規性」を参照）。

## 体裁のルール

- 本文は `branding.json` の `body_min_pt` を下回らない。収まらないときは
  **文字を小さくせず、文章を短くする**。`report_overflow()` が対象を一覧表示する。
- 箱の高さは見積りより常に高く作る。実表示は事前に読み切れないため、
  余白が無くなるより余白がある方が読みやすい。
- 画像は元のアスペクト比を保つ。出所のキャプションは画像と重ねず、外側に置く。

## 表・グラフ・注記が本文最小サイズの対象外である理由

表のセル、グラフの目盛・凡例、フッターの注記、画像に重ねるラベルは、
本文ではなく図の付属要素です。列数の多い比較表を本文と同じ大きさにすると
縦に収まらなくなるため、これらは対象外としています。ただし読める大きさ
（目安8pt以上）は確保してください。

CLI AIへの最初の依頼例:

> JOB 07として、各JOBの成果を課題ID・施策ID・根拠が追えるレポートにまとめてください。生成後は独立チェックに切り替え、修正前に指摘報告を出してください。
