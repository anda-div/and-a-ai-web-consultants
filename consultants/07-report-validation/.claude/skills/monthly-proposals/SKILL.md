# /monthly-proposals — 今月の改善提案（聞き取りから始める）

お客様は Claude Code に慣れていないことがある。**IDや台帳の言葉を覚えてもらう前提にしない。**
こちらが一覧を見せ、お客様は「はい」「2番目は実装しました」のように答えるだけで済むようにする。

台帳とシートは、案件フォルダの次の場所にある（案件によって違う場合は、`_scripts/` と `_ledger/` を探す）。

- 提案台帳：`_ledger/proposals.json`（読み書きは必ず `ledger.py` で行う。JSONを直接編集しない）
- 台帳の道具：`_scripts/report/ledger.py`（以下 `ledger.py`）
- お客様から戻った実施状況シート：`_input/実施状況/`

## 大前提

- **聞いた答えは、提案に使う前に台帳へ書き戻す。** 記録先を1つにするため。チャットで聞いただけの状態を、頭の中で使わない。
- **一度に1つだけ聞く。** まとめて聞くと、慣れていないお客様は答えにくい。
- **推測で埋めない。** 実装日が分からなければ「不明」で記録する（今日の日付で埋めない）。
- ターミナルの入力待ち（`input()` を使う対話）は使わない。お客様とのやり取りはこのチャットで行う。
- 金額・費用の話になったら、内容をメールで送ってもらうよう案内する。

## 手順

### 1. 台帳の状況を確かめる

```bash
python _scripts/report/ledger.py --check <対象月 YYYY-MM>
```

- 「戻った実施状況シートを、まだ取り込んでいません」と出たら → 手順2へ
- 出なければ → 手順3へ

### 2. 戻ったシートを取り込む（シートが届いている場合）

```bash
python _scripts/report/ledger.py --import-sheet "_input/実施状況/<シート>.xlsx"
```

違いが一覧で出る。**まだ台帳には入っていない。** お客様に要点を伝えて確かめる。

> 実施状況シートを拝見しました。次のとおり記録してよろしいでしょうか。
> ・フォームの入力項目を減らす → 9月中旬に実装済み
> ・料金表を上に出す → やらない（料金は個別見積のため）

了承をもらってから反映する。

```bash
python _scripts/report/ledger.py --import-sheet "_input/実施状況/<シート>.xlsx" --apply
```

「反映しないもの」（済んだ提案を未着手に戻す記入）が出たら、取り違えでないかをお客様に1件ずつ確かめ、
答えに応じて `--set` で直す。

シートで状況が分かったものは、手順3で聞き直さない。

### 3. 前回の提案の状況を聞く（シートが届いていない場合）

```bash
python _scripts/report/ledger.py --pending
```

未実装の提案を、お客様の言葉で番号つきで見せて、**1問ずつ**聞く。

**問1**　実装したものがあるか

> 前回までにお出しした提案のうち、まだ実装されていないと把握しているものが ○件 あります。
> 1. フォームの入力項目を減らす（8月）
> 2. 料金表を上に出す（8月）
> 3. 追従ボタンを置く（9月・実施が決まったと伺っています）
>
> このうち、すでに実装したものはありますか？　番号でお答えください。おおよその実装日も分かれば教えてください。

**問2**　状態が古いものを1件ずつ（2か月以上動いていないもの）

> 「追従ボタンを置く」は、9月に実施が決まったと伺っています。その後、まだ対応中でよろしいでしょうか？

答えが「やらないことにした」なら理由をひとことだけ、「いまは決められない」なら何待ちかと、いつ頃また見るかを聞く。

**問3**　今月のテーマ

> 今月、特に考えてほしいテーマはありますか？（例：季節の催事、法人のお客様向け、特定のページ）　特になければ「なし」で構いません。

### 4. 聞いた答えを台帳に書き戻す

1件ずつ `--set` で入れる。`--source チャット` を必ず付ける（誰の申告で変えたかが残る）。

```bash
# 実装済み（日付あり・おおよそなら月まででよい）
python _scripts/report/ledger.py --set P-2026-08-001 --status 実装済み --date 2026-09-15 --source チャット
# 実装済み（日付が分からない）
python _scripts/report/ledger.py --set P-2026-08-001 --status 実装済み --date 不明 --source チャット
# やらない
python _scripts/report/ledger.py --set P-2026-08-002 --status 却下 --note "料金は個別見積のため" --source チャット
# 保留
python _scripts/report/ledger.py --set P-2026-09-001 --status 保留 --blocked-by "リニューアル待ち" --revisit-on 2027-01 --source チャット
```

**提案より前から実装されていた**と分かったものは、実施状況シートで「実装済み（提案前から）」を選んでもらうか、
`--set <ID> --status 実装済み --date 不明 --note "提案前から実装済み" --source チャット` で入れる。

チャットの途中で「P-2026-08-001 は○月○日に実装済み」のように伝えられた場合も、同じく書き戻す。

書き戻したら、実施状況シートを出し直しておく（次回、お客様が見る一覧を台帳と揃えるため）。

```bash
python _scripts/report/ledger.py --status-sheet <対象月> --xlsx
```

### 5. 提案に進む

月初ブリーフィングを作り、その手順に従って提案を作る。

```bash
python _scripts/report/build_briefing.py <対象月>
```

ブリーフィングの「1a. 提案を出す前のルール」を必ず守る。

- 実装済み・検証済み・却下の提案と、同じ対象・同じ切り口の案は出さない
- 保留は、再検討の時期が来たものだけを理由を添えて出す
- 未着手の提案を再提示するときは、先に対象ページを撮り直し、課題がまだあるかを目で確かめる。
  課題が見当たらなければ出さずに `ledger.py --maybe-done <ID> --note "<何を見たか>"` で印を付ける
- 実装済みで実装日があるものは、レポートの「効果の検証」で前後を同じ日数で比べ、次の案の材料にする
- 問3のテーマがあれば、切り口を決めるときに考慮する（データの根拠が立たないテーマは、その旨を伝える）

### 6. レポートに載せるもの

- 各提案に **提案ID と状態** を表示する（お客様がシートと照らし合わせられるように）
- 巻末に「提案の在庫と切り口」を1ページ。材料は次で出る

```bash
python _scripts/report/ledger.py --inventory <対象月>
```

## してはいけないこと

- 状況を確かめずに、前回と同じ提案を出す
- 聞いた答えを台帳に書かずに、提案に使う
- 実装日が分からないものを、今日の日付や推測の日付で埋める
- お客様に提案IDや状態の名前（提案中・実装待ち など）を覚えてもらう前提で話す
