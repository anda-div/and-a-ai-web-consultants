# Search ConsoleのデータをPCから直接取得する

「Search Console には API がないから手作業しかない」と思われがちだが、**公式のAPIがある**。
`searchconsole.googleapis.com` として Google Cloud に登録されており、
`searchanalytics.query` で管理画面の書き出しと同じ内容が取れる。

認証は [GA4_LOCAL_FETCH.md](GA4_LOCAL_FETCH.md) と同じ仕組みで、
**スコープを1つ足して再ログインするだけ**で済む。

```
https://www.googleapis.com/auth/webmasters.readonly
```

制約は「過去16か月」「1リクエスト25,000行」。月次レポートには十分。

この文書は、管理画面の書き出しと**1セルも違わない**ファイルを作るために
必要だったことを記録する。値そのものは最初から一致した。
食い違ったのは、すべて**管理画面の表示上の作法**だった。

---

## 1. 出力の形

管理画面の「エクスポート」は、7枚のシートを持つ xlsx を作る。

| シート | dimension | 見出し |
| --- | --- | --- |
| 平均読み込み時間のチャート | `date` | 日付 |
| クエリ | `query` | 上位のクエリ |
| ページ | `page` | 上位のページ |
| 国 | `country` | 国 |
| デバイス | `device` | デバイス |
| 検索での見え方 | `searchAppearance` | 検索での見え方 |
| フィルタ | （メタ情報） | 検索タイプ／日付 |

指標列はどのシートも `クリック数 / 表示回数 / CTR / 掲載順位` の4つ。
クエリは上位1000件まで（管理画面の書き出しに合わせる）。

## 2. 合わせるべき4つの作法

### 掲載順位の丸め方が、シートによって違う

| シート | 桁 |
| --- | --- |
| 日ごとのチャート | **小数第1位**（8.5） |
| そのほか | 小数第2位（6.94） |

日ごとのシートだけ違う。APIの値をそのまま2桁で丸めると、
`8.53` と `8.5` のような差が31行ぶん出る。

CTRはどのシートも小数第4位。

### ページURLは復号された形で書き出される

APIは符号化したまま返す。管理画面は読める形にして書き出す。

```
API   https://example.com/collections/%E3%81%8A%E5%BC%81%E5%BD%93
画面  https://example.com/collections/お弁当
```

`urllib.parse.unquote` を通す。日本語URLを使うサイトでは、
ここを外すとページのシートが丸ごと不一致になる。

### 並びは3つのキーで決まる

**クリック数の降順 → 表示回数の降順 → 掲載順位の昇順。**

2つ目まででは足りない。クリックも表示回数も同じ行が普通に並ぶ
（0クリック・1表示の行など）。3つ目を入れて初めて完全に一致する。

APIの返す順は切り口によって違い、`searchAppearance` は固定順で返る。
どの切り口も、こちらで並べ直す。

### 国名は「正式名」ではない

APIは3文字コード（`jpn`）を返す。管理画面は日本語で表示する。
国は200以上あるので表を手で持たず、`babel` の訳語を使う
（3文字→2文字の変換は `pycountry`）。

ただし Search Console は正式名ではなく独自の短い表記を使うことがある。
実データと突き合わせたところ、**52件は一致し、6件が相違**した。

| コード | 管理画面 | babel の訳語 |
| --- | --- | --- |
| `usa` | 米国 | アメリカ合衆国 |
| `hkg` | 香港 | 中華人民共和国香港特別行政区 |
| `che` | スイス連邦 | スイス |
| `cze` | チェキア | チェコ |
| `dom` | ドミニカ | ドミニカ共和国 |
| `geo` | グルジア | ジョージア |

この6件だけを上書きする。新しい国が出て表記が合わなければ、そこに足す。

## 3. 表記の対応表を、実データから作る方法

既存の書き出しには日本語しか入っていない。コードとの対応は、
APIの結果と**数値で突き合わせて**割り出す。

このとき、**上から順に対応づけてはいけない。**
0クリックの行は「0クリック・1表示・CTR 0」のように数値が重なるため、
並びだけでは同じ国と断定できない。実際にそれで
`nld → トルコ` のような明らかに誤った対応表ができた。

**両方の一覧の中で数値の組み合わせが1つしかない行だけ**を対応づける。
残りは判定不能として捨てる。判定できた58件のうち52件が一致し、
6件が上の表になった。

同じ考え方は、他のツールの表記合わせにも使える。

## 4. 確かめ方

セル単位で突き合わせる。合計が合っているだけでは足りない。

比べる相手が2か月ぶんあるなら、両方で確かめる。
GA4のときは1か月ぶんしか残っておらず推移シートで代用したが、
Search Console は管理画面から何度でも書き出せるので、
**先に2か月ぶん書き出しておいてもらう**と検証が速い。

## 5. 案件での扱い

### GA4と一緒に設定する

認証の仕組みが同じなので、初回設定はまとめて1回で済む。
GA4を先に入れてからSearch Consoleを足す場合は、
**スコープが増えるので再ログインが要る**（`Insufficient Permission` で止まる）。

### 提案時に

「Search Console は API がないので手作業」と説明している同業は多い。
実際には公式APIがあり、**貴社の毎月の書き出し作業をゼロにできる**。
GA4と合わせると、数値のデータ収集は全自動になる。
