# Search Console の SNS プロパティ（Instagram など）の検索データを取る

Search Console に「プラットフォーム プロパティ」（Instagram・TikTok・X・YouTube）が加わった（2026-07）。
SNS のアカウントが **Google 検索からどう見つけられているか**（表示回数・クリック数・検索語句）が見られる。

ただし **Search Console API は、この種類のプロパティにまだ対応していない**（2026-10 に確認）。

| 試したこと | 結果 |
|---|---|
| 画面の識別子 `sc-creator-profile:instagram.com/<アカウント>` を `searchAnalytics.query` に渡す | 400（INVALID_ARGUMENT） |
| 同じ識別子で `sites.get` | 404 |
| URL の形（`https://www.instagram.com/<アカウント>/`）で渡す | 403 |
| `sites.list` | 一覧に出ない |

403 ではなく 400 なので、権限ではなく**形式として受け付けていない**。

そこで `shared/scripts/sc_platform_export.py` が、画面の「エクスポート → CSV をダウンロード」を
ブラウザ操作で行う。**取得の前に API を1回試し、通れば API で取ってブラウザは開かない。**
API が対応したら、ブラウザ操作は自然に使われなくなる。

## 1. 初回だけ：Google アカウントでサインインする

```bash
python shared/scripts/sc_platform_export.py --login-plain
```

**自動操作なしのブラウザ**が開く。タイトルの末尾が「- Chromium」の窓で Search Console に
サインインし、SNS のプロパティが一覧に出ることを確かめたら、窓を閉じる。

- 自動操作のブラウザでは、Google のサインインがメールアドレスの次の画面から進まない。
  自動操作の目印を外してすり抜ける方法は、ボット対策の回避になるので採らない。
  JOB 03 の Clarity と同じ扱い（`consultants/03-behavior-heatmap/CLARITY_CAPTURE.md` の補足4・5）
- **サインインはお客様ご自身が行う。** パスワードをスクリプト・設定ファイル・CLI AI に渡さない
- サインイン状態は `--profile`（既定 `.sc_profile`）に保存される。**Git に入れない**（`.gitignore` 登録済み）
- 同じプロファイルを2つのブラウザで同時に開かない。後から閉じた側の状態で上書きされる

## 2. 毎月の取得

```bash
python shared/scripts/sc_platform_export.py \
    --resource "sc-creator-profile:instagram.com/<アカウント>" \
    --start 2026-10-01 --end 2026-10-31 \
    --out _input/search_console_sns/2026-10
```

- `--resource` は、画面のURLの `resource_id=` の値をそのまま渡す。複数並べてよい
- プロパティごとに `--out` の下へフォルダを作り、書き出しの zip を展開して置く
- `--out/manifest.json` に、期間・プロパティ・取得日時・取り方（`api`／`browser`／`manual`）・
  API の応答・集計開始日を残す

### 集計開始日

プロパティは**登録した日からしか集計されない。** 指定期間の頭にデータが無いのは正常である。
画面の「○月○日以降のデータが表示されています」を読めたら、`data_since` として記録する。
レポートには集計開始日を必ず書き、**前月比は、まる1か月そろってから**出す。

### 取得するのは「検索パフォーマンス」の書き出しに固定する

「分析情報」の要約カードと、検索パフォーマンスの詳細の一覧では、合計がずれることがある（公式の仕様）。
数字の出どころを1つにするため、要約カードの値は使わない。

## 3. 取れなかったとき

画面の作りが変わってボタンが見つからないときは、**手で書き出す手順を表示して止まる**
（終了コード 2）。お客様が先に進めなくなることはない。

1. 表示されたURLを、ふだんのブラウザで開く
2. 期間を確かめ、「エクスポート」→「CSV をダウンロード」を押す
3. zip を、表示されたフォルダに置く（展開しなくてよい）
4. もう一度スクリプトを実行すると、置いた zip を展開して記録する（`method: manual`）

レポートの作成では、CSV が無ければ「SNS の検索データ：取得できず」として、その欄だけ飛ばして進める。

ボタンを探し直すときは `--discover` を付ける。書き出さずに、画面のボタンと文言を
`_discover.json` と `_discover.png` に残す。それを見て、スクリプトの `EXPORT_LABELS`・`CSV_LABELS` を直す。

## 4. レポートへの載せ方

- 欄の名前は「（SNS名）の Google 検索からの見つけられ方」とする。
  **SNS の中での反応（いいね・フォロワー・アプリ内の表示回数）は含まない**ことが分かる名前にする
- 指標：クリック数・表示回数・CTR・平均掲載順位、上位の検索語句、上位の投稿
- 集計開始日を必ず書く
- サイトの Search Console の数字と**足し合わせない。** 別の表にする

## 5. 確かめたこと・まだ確かめていないこと

| 項目 | 状態 |
|---|---|
| API が 400 を返し、ブラウザでの取得へ進むこと | 実際のプロパティで確認（2026-10-24） |
| 手で置いた zip の展開と記録、API が通ったときにブラウザを開かないこと | テストで確認（`shared/tests/test_sc_platform_export.py`） |
| 画面のURLで期間が指定どおりになること | **未確認** |
| 「エクスポート」「CSV をダウンロード」の押し方、書き出しの zip の中身 | **未確認** |
| 集計開始日の表示の読み取り | **未確認**（日本語・英語の想定の形だけテスト済み） |

未確認の3つは、サインインした実際の画面で一度通して確かめる。
