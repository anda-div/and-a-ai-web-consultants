# AIっぽさ撲滅憲法

2026年10月18日 制定（株式会社and,a）。and,a が社外に出す**すべての成果物**と、このリポジトリのコンサルタントが生成するレポート・改善提案に適用する。
提案書・報告書・手順書・メール・チャットの文面・X の投稿・本の原稿。社内向けの資料も、社外に転用しうるものは同じ。

きっかけ：2026年10月、ある代理店様から、当社の提案資料について「可能な範囲でAIらしさを軽減してほしい」とのご指摘をいただいた。
読み直すと、見出しの6割が「A：B」の形だった。**AIを使ったかどうかの問題ではなく、表現の問題**として扱う。

---

## 前文

読み手に「この人が、私のために書いた」と感じてもらう。それが成果物の信頼になる。
AIらしさとは、「誰に向けても同じに見える」こと。固有の事情、迷い、判断の理由が消え、整いすぎた形だけが残った状態をいう。
この憲法は、その形を具体的な型として挙げ、提出前に取り除く手順を定める。

---

## 第1章　見出し

**第1条** 見出しを「A：B」の形で書かない。コロン（：）で前後をつなぐ見出しは、一文に書き直す。
- ×「学習の流れ：PDCAの上に5回を置く」　○「5回の研修を、PDCAの順に進めます」
- ×「1回あたりの時間配分：90分版と120分版」　○「1回は90分。発表のある第4回だけ120分です」
- 回や章の番号を付けるときは、コロンではなく全角の空白で区切る。「第1回　分析の基礎とPDCA入門」

**第2条** 見出しだけを順に読んで、話の流れが分かるように書く。「〜について」「〜の全体像」「〜とは」「〜のポイント」だけの見出しは書かない。

**第3条** 見出しは、その枚で読み手に持ち帰ってほしい一文にする。名詞で終わる見出しは、表や一覧の枚に限る。

## 第2章　言葉

**第4条** 比喩の動詞を使わない。その場で実際にする動作の言葉を使う。
- 置く・乗せる・回す（PDCAを回す）・繋げる・つなぐ・落とし込む・寄り添う・伴走する・加速する・紐づける・立ち上げる（事業以外）
- ○ 進める・使う・書く・決める・確かめる・送る・測る

**第5条** 一般論の言葉を、その案件の言葉に置き換える。次の語は、見つけたら必ず言い換えを考える。
- 可視化・見える化・最適化・効率化・実現・活用・推進・強化・向上・促進・定着・価値・貢献・包括的・体系的・戦略的・シームレス・ソリューション・アプローチ・インサイト・ナレッジ・エンゲージメント（GA4の指標名を除く）
- ×「データを可視化し、意思決定を支援します」　○「毎月1日に、先月の問い合わせ数と、その内訳の表をお送りします」

**第6条** 文のつなぎの常套句を使わない。
- 「〜することで」「〜を通じて」「〜において」「〜という観点から」「〜に繋がる」「〜が鍵となる」「〜が重要です」「〜と言えるでしょう」「結論から言うと」「まず初めに」「様々な」「適切な」「効果的な」「しっかりと」「ぜひ」
- 「〜することで」は、原因と結果を2つの文に分ける。「〜が重要です」は、なぜ重要かを書けば消える。

**第7条** 記号と飾りを使わない。「！」、絵文字、「✓」「▶」「★」「■」の見出し記号。太字は1枚に1か所まで。

**第8条** 「解像度」「論点」「仮説」など、and,a が自分の言葉として使っている語は、この章の対象にしない。判断に迷ったら責任者（中田）に確かめる。

## 第3章　並びと数

**第9条** 数をそろえて並べない。「3つのポイント」「5つの方針」は、中身が3つ・5つあるときだけ書く。4つあれば4つ、2つなら2つ。
- 同じ資料の中で、各枚の箇条書きがすべて同じ数（毎回4項目）になっていたら、疑う。

**第10条** 箇条書きの各項目を、同じ長さにそろえない。長い項目と短い項目があってよい。箇条書きの階層は2段まで。

**第11条** 名詞を「／」「・」でつないだ列を、本文に書かない。短い文にほどき、読点と「と」「や」でつなぐ。出典や品番の列挙、表の中は例外。
- ×「論点カード（題材ページ／悪い指標／比較期間／現在値）」　○「論点カードには、題材ページと悪い指標、比較する期間、現在の値を書きます」

**第12条** 同じ型の枚を続けない。「左に図、右に3つの箇条書き」が5枚続いたら、どれか1枚は表か、文章か、1つの大きな数字にする。

## 第4章　口調と文

**第13条** 体言止めを続けない。説明の欄は「です・ます」の文で書く。表の中で短く書く場合も、「ねらい」「理由」の欄は文にする。

**第14条** 一文に一つのことだけ書く。「〜し、〜し、〜します」と3つ以上つなげない。

**第15条** 読み手に向けて書く。「〜が求められます」「〜が必要です」と誰にともなく書かず、「貴社では〜」「私は〜と考えます」「〜をお願いしたいです」と主語を立てる。

**第16条** 断定を避ける言い回しを重ねない。「〜と思われます」「〜と考えられます」「〜の可能性があります」が続いたら、分かっていること・分かっていないことに分けて書き直す。

## 第5章　固有性（人が書いた証拠）

**第17条** 先方の言葉を使う。ご提案時の表現、会議で出た言葉、先方の資料の見出し、実際のページ名や商品名。
- 一般論に見える文は、先方の固有名詞を1つ入れると、その会社の文になる。

**第18条** 経緯と日付を書く。「10月8日のご依頼を受けて」「前回の第1版では〜でしたが」。経緯は、人が書いたことのいちばん分かりやすい証拠になる。

**第19条** 迷いと判断の理由を書く。「AとBで迷いましたが、Bにしました。理由は〜」。きれいに整った結論だけの資料は、人の判断が見えない。

**第20条** 数字は実測を書く。「約」「多数」「大幅に」の代わりに、数えた数と、数えた範囲を書く。
- ×「多くのスライドで」　○「26枚のうち16枚で」

**第21条** 「例えば」の後には、実際にあった例を書く。作った例を書くときは、作った例だと分かるように書く。

## 第6章　図とレイアウト

**第22条** 次の意匠は、AIが作った資料の目印になっている。使わない。
- 見出しの下の短いアクセント線
- 枚の上下や左端の色帯、カードの片側だけの色の縁
- 丸の中にアイコンを置いた横並び（3〜4個）
- 同じ大きさのカードを等間隔に並べた格子で、各カードの文字量まで同じもの
- 矢印で円を描いた循環図（PDCA の図を除く）

**第23条** 図は、その案件の実物を使う。実際の画面、実際のページ、実際の数字のグラフ。概念図だけの枚を2枚続けない。

**第24条** 文字の大きさは読み手に合わせる。本文14pt未満、注10pt未満にして詰め込まない。入らなければ、枚を分けるか、言葉を削る。

## 第7章　提出前の点検

**第25条** 提出の前に、作った本人（人、または作成を担当した Claude Code のセッション）が、次の順に全ページを点検する。

| 順 | 見るもの | 確かめ方 |
|---|---|---|
| 1 | 見出し | 見出しだけを通して読む。「A：B」の形がないか。流れが分かるか |
| 2 | 言葉 | 第4〜6条の語を検索して、一つずつ言い換える（下の点検スクリプトで機械的に拾える） |
| 3 | 数と長さ | 箇条書きの数が毎回同じになっていないか。項目の長さがそろいすぎていないか |
| 4 | 口調 | 説明の欄が体言止めばかりでないか。「です・ます」の文があるか |
| 5 | 固有性 | 先方の言葉・固有名詞・日付・経緯・判断の理由が入っているか |
| 6 | 図 | 第22条の意匠がないか |
| 7 | 音読 | 声に出して読む。詰まる箇所、意味が一度で取れない箇所を直す |

**第26条** 点検の結果は、提出時に一行で残す（作業記録や引き継ぎファイルに「憲法の点検済み。直した箇所：見出し6、語3」など）。

**第27条** 機械点検は `shared/writing-standard/ai_check.py` で行う。pptx・docx・md・txt を読み、第1条・第4〜7条・第9条・第11条・第13条に当たりそうな箇所を列挙する。
機械点検は人の点検の代わりにならない。拾ったものを人が読んで決める。

```
python shared/writing-standard/ai_check.py 資料.pptx
```

## 第8章　適用範囲と例外

**第28条** この憲法は、and,a が社外に出すすべての成果物に適用する。案件や相手を問わない。

**第29条** 次は例外とする。
- 先方の文書・提案書・画面の名称を引用する箇所（原文のまま）
- 用語の定義、品番、出典の列挙、法務・契約の文面
- GA4・Search Console などの指標名・機能名

**第30条** 憲法に当てはめると意味が変わる・分かりにくくなる箇所は、憲法より意味を優先し、その判断を記録に残す。迷ったら責任者（中田）に確かめる。
