# GA4のデータを、GASではなくPCから直接取得する

これまでは GAS をお客様に実行していただき、Excel をダウンロードして配置して
いただいていた。これを、AIが自分で取得できるようにする。お客様の手数が減るほど、
他の見込み客への展開もしやすくなる。

**出力する xlsx は GAS と同じ形にする。** シート名・列見出し・並び順・丸め方まで
そろえれば、下流のレポート生成は1行も変えなくてよい。確定値がファイルとして残る
ので、翌月の前後比較と検収の根拠も従来どおり守られる。

この文書は、**実際に詰まった順**に書いてある。同じ環境なら同じ順で詰まる。

---

## 1. 認証：gcloud 内蔵のクライアントIDでは通らない

`gcloud auth application-default login --scopes=...analytics.readonly` は、
ブラウザに「**このアプリはブロックされます**」と出て失敗する。gcloud 自身も
実行時に警告を出している。

```
WARNING:
The following scopes will be blocked soon for the default client ID:
https://www.googleapis.com/auth/analytics.readonly.
To use these scopes, you must provide your own client ID or use
service account impersonation.
```

環境の問題ではなく、Google の方針変更である。**GA4 の MCP サーバーの公式手順も
同じコマンドを案内している**ので、あちらも同じ壁に当たる。

### 対処：自前の OAuth クライアントIDを作る

Google Cloud のプロジェクトで、1回だけ作る。API では作れないので画面操作になる。

1. 「API とサービス」→「OAuth 同意画面」
   - 対象ユーザー: **「内部」**
   - サポートメール・連絡先メールを設定
2. 「クライアント」→「クライアントを作成」
   - 種類: **「デスクトップ アプリ」**
   - 作成後、JSON をダウンロード
3. JSON を `~/.and-a/oauth_client.json` へ置く
4. `shared\scripts\adc_login.cmd <プロジェクトID>` を実行

**「内部」が要点。** 「外部」かつ未審査だと、更新トークンが**7日で失効**する。
月次の自動取得が毎週壊れることになる。「内部」にできるのは、そのプロジェクトが
Google Workspace の組織配下にある場合。組織がなければ、審査を通すか、
サービスアカウントの権限借用に切り替える。

サインインするアカウントは、**対象のGA4プロパティの閲覧権限を持つもの**。
クライアントから招待を受ける専用アカウントがあるなら、それを使う。

### 「プロジェクトが存在しない」と言われたら

Cloud コンソールでプロジェクトが見えないときは、たいてい次のどちらか。

- ブラウザでログイン中のアカウントに、そのプロジェクトのIAM権限がない
- プロジェクト選択の左上が特定の組織で絞り込まれている

Workspace の管理者権限（アカウント・2段階認証）と、Cloud の IAM は**別系統**。
管理者だからといって全プロジェクトが見えるわけではない。

### CSRF Warning! State not equal と出たら

```
ERROR: (mismatching_state) CSRF Warning! State not equal in request and response.
```

前回の認証プロセスが `localhost:8085` を掴んだまま残っていて、そちらへ
コールバックが届いている。中断した試行があると起きる。

```
netstat -ano | findstr :8085        待機しているプロセスIDを調べる
taskkill /PID <ID> /F               終了させてからやり直す
```

## 2. 一致の確かめ方：合計ではなく、1セルずつ

「合計が合っている」では足りない。`compare_ga4.py` でセル単位に突き合わせる。

```
python compare_ga4.py GASの.xlsx ローカル取得の.xlsx
```

### 過去1か月分しか GAS 出力が残っていないとき

2か月目を確かめたいのに、比べる相手がない。このとき、**GAS が出した
「6ヶ月推移」シートを使う**と、追加の作業なしに別の月を検証できる。

そのシートには過去6か月の月次合計が入っている。これは GAS が GA4 から取った
確定値なので、別の月を取得したときの推移シートや当月合計と一致するはずである。
1回の取得で 5か月 × 4指標 を独立に確かめられる。

## 3. 丸め方が違う（合計は合うのに小数第1位だけずれる）

GAS は JavaScript の `Math.round`、Python は `round()`。**0.5 の扱いが違う。**

```
JavaScript  Math.round(6.25 * 10) = 63  → 6.3    0.5 は必ず切り上げ
Python      round(62.5)           = 62  → 6.2    0.5 は偶数側へ
```

直帰率などの列にそのまま出る。実例では 5,714 セル中 **4セル**だけが
この理由で食い違った。見つけにくい類のもので、**セル単位で比べていなければ
気づけない**（合計は完全に合う）。

GAS 側にそろえる。負の数も JavaScript に合わせる（`Math.round(-2.5) = -2`）。

```python
import math

def js_round(x: float) -> int:
    """JavaScript の Math.round と同じ丸め方。"""
    return math.floor(x + 0.5)
```

## 4. 一時的なエラーで取得が丸ごと落ちる

```
google.api_core.exceptions.DeadlineExceeded: 504 Deadline Exceeded
```

ページ間遷移など行数の多い問い合わせで起きる。1回落ちると月次の取得が
そこで止まるので、待ってやり直す。504・503・429 は再試行の対象にする。

- 待ち時間は 5秒 → 10秒 → 20秒 と伸ばす
- 問い合わせ自体のタイムアウトも延ばす（既定は短い）

## 5. セキュリティソフトのHTTPS検査

別の落とし穴があり、`shared/TLS_INSPECTION.md` に分けて書いてある。
**着手前に一度切り分けておく**こと。

```
python shared/scripts/tls_env.py
```

## 6. 案件での扱い

### 切り替えの判断

GAS の値と一致することを確かめてから切り替える。確かめる条件は次の5つ。

1. 1か月分がセル単位で完全一致すること
2. 別の月でも一致すること（比べる相手がなければ推移シートで代用）
3. 一時的なエラーから自力で回復すること
4. 認証が切れたときの入れ直し手順が書けること
5. セキュリティソフトの検査下でも動き、その手順が書けること

「3か月動かしてから」といった期間で区切らない。**確かめるべきことが
確かめられたかどうか**で決める。期間はお客様を待たせる理由にならない。

### お客様が自走される場合

お客様のプロジェクトで、OAuth クライアントの作成が必要になる。
1と2の手順を、画面の名前どおりにマニュアルへ書く。特に次を落とさない。

- **「内部」を選ぶこと**と、その理由（外部だと7日で切れる）
- サインインすべきアカウント（GA4の閲覧権限を持つもの）
- 認証が切れたときに、同じコマンドをもう一度実行すればよいこと

### 提案時に触れておく

GAS からローカル取得へ移す利点を説明する際、初期設定に画面操作が
1回必要な点は先に言う。後から出すと不信を招く。
